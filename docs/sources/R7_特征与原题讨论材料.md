# R7：假设与未来推演——题型特征、原题与 pipeline 讨论材料

整理日期：2026-09-08。分类基线：项目当前的九类方案，benchmark_pipeline_reclassification_v04.xlsx。

**R7 的核心是：从有来源的已知事实出发，在明确的观察范围和假设条件下，判断尚未观察到的未来，或条件改变后的替代结果。** 系统需要保存“实际看到了什么”“题目改变了什么”“哪些结果是推演出来的”这三种信息，并能检查它们之间的约束。

本文覆盖分类表中 **4 个默认 R7 原生入口和 4 个条件性涉及 R7 的入口**，整理 **30 道完整例题：21 道 R7 机制例题、9 道边界例题**。每道均保留英文题干、完整选项、来源定位和中文题意；28 道有来源答案，2 道论文原例未标答案。附录另列 Video-MME-v2 两个相关原生标签下 **全部 80 道题的完整题干索引**，便于继续选题。

**建议带给导师讨论的主张：先建设共用的事实获取、假设表示和候选核验流程，再按问题需求选择不同的推演方式。** 现有原题支持至少区分动作预测、情境预测、物理反事实、变量／规则反事实、趋势外推五组机制。是否需要物理仿真、显式因果图或更大的世界模型，应由具体题目的证据缺口和实验决定。

本文核对了分类工作簿、原始标注、相关论文和 MVBench 官方加载逻辑；**没有观看原视频或运行模型实验**。来源答案属于 benchmark 标注。逐题机制、最小证据需求和 pipeline 建议是本文分析，不能当作已完成的视频验证或实测结论。

## 1. R7 的定义、覆盖范围与九类边界

### 1.1 项目已有定义

分类表对 R7 的定义如下，本文沿用其核心含义。[分类基线 F01](#f01)

### 1.4 放在九类体系中的位置

| 主类 | 项目名称 | 与 R7 的区别或可复用内容 |
| --- | --- | --- |
| R1 | 定向定位与局部取证 | 提供当前物体、属性、台词、局部事件等事实；答案若已明示，可直接在此完成 |
| R2 | 连续动态与实体状态追踪 | 提供身份、运动、轨迹、周期和状态转移；稳定周期下一相位可以仍由 R2 查询 |
| R3 | 事件账本与时序归约 | 提供发生次数、事件顺序、时间锚点；已发生后继事件属于时序查询 |
| R4 | 清单构建与集合归约 | 提供对象集合、计划清单和差集；“还没买什么”并不要求推演未来 |
| R5 | 分段全局综合 | 提供跨片段的重要事实背景；可作为叙事／生态未来预测的输入 |
| R6 | 证据约束关系推理 | 解释已发生事件的原因、动机和关系；R7 进一步改变条件或推向未见结果 |
| **R7** | **假设与未来推演** | **显式保存观察范围、题设干预及候选未来／替代状态** |
| R8 | 视觉符号与约束求解 | 提供变量绑定、算术和规则计算；若主任务有干预语义，仍可由 R7 编排 |
| R9 | 空间场景建模与查询 | 提供对象位置、朝向和参考系；导航下一步并不自动等同未来世界预测 |

主类说明“主要维护什么状态、完成什么操作”，组件说明“取得答案需要哪些能力”。R7 调用计数或空间组件，不要求把一道题拆成多个独立 agent。

### 1.5 最重要的四种边界判断

**第一，后继检索与未见未来要分开。** “拿食物后做了什么”在完整输入中可以是 R3；“截止这一刻后会做什么”才具有真正预测语义。必须先确认正式可访问内容，不能只看 next、after、will。

**第二，实际因果解释与反事实要分开。** “为什么撞车”可归 R6；“如果抓地力更好，会怎样”需要构建替代条件。后者即便调用同一组事实，也多出干预及其后果传播。

**第三，时间截断与反事实世界分离要分开。** 对未来动作预测，要遵守正式观察区间，禁止读被预测后续。对反事实，如果协议允许读取完整的实际视频，可以利用实际发生的运动帮助理解对象和机制；关键是不能把实际后果直接当作干预后的后果。干预时刻并不自动等于事实视频的读取截止。

**第四，规则和趋势可以被轻量执行。** 浇花次数重算、武器升级、图表趋势外推未必需要生成未来视频。需先确定变量、约束和模型假设，再选择可复算的操作。

## 2. 五组机制与共性特征

### 2.1 五组内部机制

S1–S5 是本文用于讨论证据和执行差异的分组，不修改现有 R1–R9，也不预设要实现五套独立 pipeline。

| 分组 | 所问结果 | 需要保存的状态 | 最有用的观察 | 候选执行方式 | 代表题 |
| --- | --- | --- | --- | --- | --- |
| S1 局部动作预测 | 人或智能体接下来采取什么动作 | 当前姿态、持物、动作阶段、可行动对象 | 正式观察区间末尾及必要的前置动作 | 当前状态与动作前提匹配，比较下一步候选 | E01、E02；E09/E11 的最后一步 |
| S2 情境／叙事预测 | 后续选择、情绪序列、生态结果 | 人物态度、相关历史、情境规律、待决事件 | 多个有判别力的历史片段与当前情境 | 带事实依据的候选比较，保留不确定性 | E16、E18、E21 |
| S3 物理／时空反事实 | 删除对象、改位置、改拍面、改时机后发生什么 | 对象身份、运动、接触、空间关系、干预作用位置 | 接触或决策前后的短片段、相关空间视角 | 定性关系传播；必要时增加数值状态或仿真 | E03、E06–E09、E12–E15 |
| S4 变量／规则反事实 | 改次数、属性或规则触发后，结果如何 | 原始变量、替代赋值、规则表、结果依赖 | 精确计数、属性读取、规则示例 | 复制事实状态、施加干预、计算依赖结果 | E05、E10、E11、E14 |
| S5 趋势外推 | 指定变化方式继续后，数值或排名如何 | 实体身份、时间轴、水平与速率、基期、预测期限 | 指定历史区间的多个时刻 | 显式趋势估计、条件外推与排序 | E17、E19、E20 |

同一题可以组合机制。例如 E09 先做物理反事实再预测行动；E11 先执行升级规则再选行动；E18 虽属官方 Future Event Prediction，题干又明确设定新情境。这说明“未来”与“有干预”应是可组合的属性。

### 2.2 共性一：证据具有不同身份

建议至少区分下面五种记录：

| 记录类型 | 例子 | 使用方式 |
| --- | --- | --- |
| 观察事实 | 截止时人物拿着书；某次浇水发生于特定时间 | 必须有画面、音频或允许文本的来源 |
| 题设条件 | 假设移除圆柱；其他条件保持不变 | 来自题干，不能伪装成画面观察 |
| 机制／规则 | 视频展示的武器升级顺序；采用的趋势模型 | 记录依据、适用范围及是否为外部先验 |
| 推演结果 | 移除后某次碰撞不会发生；下一武器是什么 | 必须指向所用事实与条件，不能回写为实际历史 |
| 未知信息 | 接触点被遮挡；实际原始计数无法确定 | 保留未知，必要时补看，不使用答案填补 |

这项区分比要求模型生成很长的推理文本更容易检查。短事实表已经可能足够；复杂图结构要有明确用途。

### 2.3 共性二：干预应精确，影响可以传播

“只改变题设指定条件”应理解为：只直接修改指定变量，保持未受影响的背景条件；**由该变量引起的下游状态仍需重新计算。**

E03 删除圆柱后，其他物体的碰撞与速度可以改变。若冻结所有其他轨迹，等于没有传播干预；若又随意修改它们的初始速度或身份，则引入了题设之外的变化。

需要讨论的字段包括：被干预对象、被改属性或事件、操作类型、替代值、作用时刻／区间、必须保持不变的条件、受影响的下游关系。操作既可能是 remove/set/swap，也可能是“保持不死亡”“延迟两秒”或“继续沿用某个趋势”。

### 2.4 共性三：先消除事实歧义，再扩大推演复杂度

R7 常见的失败起点仍是基础取证：

- E06 的比分或球衣号码认错，后面的战术推演就会围绕错误事件进行。
- E08 的拍面和接触方向看不清，语言层无法可靠补齐物理状态。
- E12 把“第一位真正成功者”定位错，迁移的技巧也会错。
- E20 把历史倒数第三名当成当前倒数第三名，会持续追踪错误实体。

因此，“增加推演步数”与“增加有针对性的观察”必须分开评估。补看应针对候选间尚未解决的事实差异，且仍遵守原观察权限。

### 2.5 共性四：候选选项会决定需要多少证据

E01 只区分四种动作前提；E07 则要区分“避开碰撞”与“完成整个配送”；E11 同时要求武器和下一动作；E19 同时比较两个未来情境。

可以把每个选项分解成可检查的原子结论：主体、动作／关系、对象、时刻、强弱程度和附加后果。判断一项被支持，需要检查它的全部关键结论；只匹配其中一个词不足以支持完整选项。

选项可以帮助制定观察计划，但不能作为事实来源。例如“路牌”“白西装”“某人会摘下耳机”出现在候选里，只表示一个待检验的可能性。

### 2.6 共性五：时间轴可能不止一条

| 时间概念 | 示例 | 不能混淆为 |
| --- | --- | --- |
| 媒体时间 | MVBench start=3.2、end=13.625 秒 | 永远从 0 秒开始的前缀 |
| 查询锚点 | 绿色关卡开始；字幕出现后的第一发球 | 全视频开始 |
| 干预时刻 | 发球接触瞬间；发车信号时刻 | 自动禁止读取其后一切实际画面的截止 |
| 预测目标时间 | 下一个动作；2030 年 | 模型可直接观看的真实后继片段 |
| 图表语义时间 | 2021 年趋势、2025 年趋势 | 视频文件中的第 2021 或第 2025 秒 |

E19、E20 尤其适合检验媒体时间、图表年份、参考区间与预测期限的绑定。

### 2.7 共性六：满足约束不等于未来已经确定

计数干预在事实和规则确定后，可能得到唯一结果。人物选择、旁观者情绪和生态演变通常仍有多个合理结果。pipeline 应区分“违反已知条件”“获得具体支持”“目前信息不足”。

若 benchmark 要求必须输出一个字母，系统可以在预算内选择证据支持最充分的一项，同时在内部保留歧义与缺口。模型自报的 0.9 置信度不能直接视为校准后的 90% 正确概率。

## 5. 可讨论的 pipeline 方案

### 5.1 设计目标与共用流程

拟定的目标是：**让每个未来／替代结论都能追溯到合法取得的事实、明确的条件和适用的推演操作。** 先比较轻量方案是否减少定位、身份、变量串用与约束违反，再考虑更重的模型。

~~~mermaid
flowchart TD
    Q["题目、选项与正式输入协议"] --> C["编译目标、观察范围与干预"]
    C --> O["按需要取得局部事实、轨迹或账本"]
    O --> F["冻结带来源的事实状态"]
    F --> S["选择适用的推演方式"]
    S --> A["动作或情境候选比较"]
    S --> B["物理关系与状态传播"]
    S --> D["变量修改与规则计算"]
    S --> T["趋势估计与条件外推"]
    A --> V["检查约束、反证和额外假设"]
    B --> V
    D --> V
    T --> V
    V --> N{"还缺可观察的关键事实？"}
    N -->|"有预算且在允许范围内"| O
    N -->|"证据足够或预算用尽"| R["输出候选及内部证据记录"]
~~~

这是一个共享流程下的执行方式选择。某题可以先做规则计算、再做行动比较；无需为每种组合再建立独立完整 agent。

### 5.2 第一步：编译问题与输入合同

在看视频前先整理以下信息，缺失时显式保留未知：

| 字段 | 需要表达什么 | 典型错误 |
| --- | --- | --- |
| native_task | 原始 benchmark 标签 | 被直接当作逐题真值 |
| execution_mode | 未来预测／反事实／两者组合／待审 | 所有带 next 的题都进预测 |
| observation_scope | 合法媒体、时间范围、字幕和音频条件及依据 | 有 start 却仍从 0 秒读取 |
| query_anchor | 题中比分、人物、字幕、动作阶段等定位条件 | 将第五次与第五个对象混淆 |
| target | 预测对象、变量、关系和目标时刻 | 把最可能行为写成已发生事实 |
| intervention | 对象、操作、替代条件、时点和不变条件 | 未指定的外部变量被随意修改 |
| candidate_schema | 原始候选顺序、数量与复合结论 | 固定四选一；只判断复合选项一半 |
| unresolved | 截止缺失、实体指代、规则歧义 | 用常识或答案键自动补空 |

观察范围的依据优先来自正式 benchmark 协议和加载器；题干可以进一步限制查询范围。不能因题干不写截止就默认可以读未来，也不能为官方数据自行发明截止后仍称完全复现官方评测。

**Video-MME-v2 的具体待办：** 当前 parquet 字段不足以确定所有预测题的截断规则。进入正式实验前，应核对实际发布媒体、官方评测入口及具体题意；需要人工构造截断的样本，单独登记新协议与目标范围。本文没有把这项待办冒称已经完成。

### 5.3 第二步：建立由问题决定的事实观察计划

| 场景 | 起始观察计划 | 补看的触发条件 | 可复用组件 |
| --- | --- | --- | --- |
| 明确 start/end 的动作预测 | 覆盖允许区间，重点保留末尾动作过程 | 持物、接触或完成阶段仍有歧义 | R1 局部取证、R2 动态状态 |
| 带比分／字幕的反事实 | 先定位锚点，再看决定性短片段 | 身份、接触方向、事件次序不清 | R1 定位、R2 状态、R3 锚点 |
| 计数反事实 | 先确定目标与计数单位，再覆盖指定范围 | 相邻窗口重复计数或漏掉边界事件 | R3 事件账本 |
| 多人物／多次尝试 | 分别定位失败者、成功者、规则示例 | 技巧与失败原因不能对应 | R1 多锚点、R6 关系核对 |
| 图表趋势 | 读取指定语义年份的多时刻数据 | 身份漂移、速率模型或临界名次不确定 | R1 OCR、R2 变化、R8 计算 |
| 长程情境预测 | 分段获得相关背景，再回看有判别力片段 | 候选包含当前事实无法支持的动机或因果 | R5 分段事实、R6 关系 |

所有计划受预算约束。短动作、图表趋势和叙事情境的时间尺度不同，初版不宜只设一个全局固定“补看 5 秒”的规则。

### 5.4 第三步：冻结事实状态，派生假设状态

事实状态至少记录对象 ID、属性或关系、媒体时间、来源模态与证据片段。干预后新建假设状态，保留其父事实状态和干预来源。

可以采用轻量的关系：

~~~text
事实状态 F
  + 题设干预 I
  + 适用规则或动态假设 M
  -> 假设状态 H
  -> 各候选结果及其依据
~~~

这是一种工程记录方式，不代表已经从观察视频识别出唯一、完备的因果模型。对隐藏状态有多个合理解释时，应保留少量与答案有关的分支，或标记不确定。

建议使用简短字段保存结果依据，不要求自由生成整段冗长思维过程。每个结果节点只记录输入事实 ID、采用的规则／条件和输出状态，便于人工检查。

### 5.5 第四步：选择最低必要推演方式

**A. 动作与情境候选比较。** 对每个候选检查当前前提、情境支持、反证和额外假设。E01 看动作阶段；E16 看人物态度；E18 看历史情境规律。允许预测不唯一，不能只因“不矛盾”就把候选写成已证实。

**B. 物理关系或状态传播。** 从接触、遮挡、相对方向、支撑等关系开始。若几个候选必须依赖速度大小、距离或精确时机才能区分，再增加数值状态。物理仿真器本身不解决输入状态估计错误；仿真参数必须来自观察或明确假设，不能来自隐藏的 benchmark 场景真值。

**C. 变量修改和规则执行。** 适用于 E05、E11，以及一部分 E10/E14。可先用字典、规则表和少量算子实现，记录输入变量来源、修改操作和计算结果。严禁通过选项答案反推未知输入。

**D. 趋势估计和外推。** 明确身份、指标、基期和期限后，再选速率模型。如果有依据采用恒定绝对速率，可写成：

~~~text
速率 r_i = (x_i(t_b) - x_i(t_a)) / (t_b - t_a)
预测 x_i(t_target) = x_i(t_base) + r_i × (t_target - t_base)
最后按预测值排序
~~~

其中估计速率的区间与外推基期可以不同，E20 就需要单独绑定。上述公式只是**适用条件明确时的候选模型**；题目若按比例变化、只给定性趋势或强调特殊规则，不能无条件套用。接近名次交换时，要检查测量误差是否会改变排序。

### 5.6 E05 的最小执行示意

可先用浇花题检验整个 R7 记录链条：

1. 找到绿色关卡的开始，把前 15 秒转换为正确的媒体时间区间。
2. 为左、中、右花建立稳定 ID，记录该区间各次浇水事件。
3. 计算原始次数 cL、cM、cR，并检查重复窗口、边界和漏检。
4. 将题干编译为 cL'=cL、cR'=cL、cM'=cM+1。
5. 依据题目与视频规则绑定最高／最矮花。若其高度随干预变化，重新确定排序；如指原对象，保留原身份。
6. 输出对应两项次数，再映射到原始候选。

这段示意没有填入未知事实值。来源答案 F=(3,1) 只用于最后评测，不进入第 2–5 步。它可以验证“取证正确但干预执行错误”和“原始计数就错了”这两类问题是否能被分开。

### 5.7 第五步：候选核验与针对性补看

可为每个选项维护一个紧凑表：

| 核验项 | 问题 |
| --- | --- |
| 实体绑定 | 选项描述是否对应同一组已观察对象？ |
| 观察合规 | 使用的事实是否来自正式允许的媒体范围与模态？ |
| 干预一致 | 指定修改是否实际生效？未受影响的条件是否保持？ |
| 传播完整 | 被干预影响的关键下游状态是否重算？ |
| 复合结论 | 武器、行动、两个时间场景等子结论是否都满足？ |
| 额外假设 | 候选是否新增没有依据的动机、对象或更远后果？ |
| 反证 | 是否存在与候选直接冲突的已知事实？ |
| 可补证性 | 缺口是否可以在当前观察范围内用一次明确的补看解决？ |

核验器可以是规则检查、计算检查、模型局部复核的组合。再次把相同输入交给同一模型，不等同于获得独立证据；多次一致也不能自动证明正确。

补看循环只解决可观察的事实缺口。若问题在于多个合理未来都符合事实，继续观看同一片段未必有帮助，应保留剩余歧义并按题目要求选择候选。

### 5.8 何时停止

建议区分三种终止：

- **可计算结果已确定：** 关键事实、变量绑定、干预和计算核验通过，结果唯一映射到候选。
- **概率性候选已有充分比较：** 关键候选差异已检查，选中项有具体支持，重要反证已处理。记录哪些内容仍属于可能性判断。
- **预算耗尽或不可观察：** 输出协议要求的最佳候选，同时在内部标记事实缺口、未决分支和终止原因。

初版不应将“模型表示很确定”设为唯一停止条件，也不应无限补看直到得到与答案键一致的中间结论。

### 5.9 与现有项目的衔接

既有 R1/R3/R4/R5 设计把 R7 列在当时新增实现范围之外，但允许复用已观察事实。本次建议把 R7 作为新的讨论方向，在已有证据接口之上增加以下责任，而非重新实现所有取证工具：

| 可以复用的能力 | R7 需要新增或明确的责任 |
| --- | --- |
| 局部检索、帧／片段读取、OCR 与事实记录 | 把正式观察范围传入所有观察、检索与缓存读取接口 |
| 事件账本、对象身份、简单集合与算术 | 保存不可被假设覆盖的事实版本，以及干预副本 |
| 输出候选映射、预算和调用日志 | 保存候选所用事实、假设、规则及终止原因 |
| 现有诊断与复核习惯 | 增加未来信息使用、干预遗漏、场景串用和模型假设错误的归因 |

这是设计建议。本次没有修改 R7 代码，也没有验证现有实现已经满足这些接口。若继续沿用既有固定 Qwen3-VL-8B-Instruct 的研究设置，应把“证据组织改进”与“更换模型带来的能力变化”分别实验。

## 6. 实验设计与导师讨论清单

### 6.1 首轮样本怎么选

建议先选 **12 道机制开发题，加 4 道边界诊断题**：

| 目的 | 建议题目 | 希望检查的机制 |
| --- | --- | --- |
| 动作与时间边界 | E01、E02 | 区间末尾状态；start 非零；持物和动作阶段 |
| 对象移除与候选接口 | E03、E04 | 反事实传播；实体别名；候选数不同 |
| 变量干预 | E05 | 事实计数、变量修改、最高／最矮身份绑定 |
| 局部物理后果 | E07 | 直接后果与额外远期承诺 |
| 多步物理链 | E08、E09 | 中间状态、误差传播与同视频依赖 |
| 情境预测 | E16 | 预测目标是否可见；人物事实支持 |
| 趋势与多时点 | E17、E19、E20 | 外推假设、多场景与历史身份绑定 |
| 边界诊断，单独报告 | B04、B05、B07、B08 | 周期、后继检索、标签偏差与原因解释 |

这里是开发与诊断建议，数量不足以支持总体性能结论。先核验视频和观察协议，再冻结样本与分组规则；不要根据某个模型是否答对来事后挑选“核心集”。

E08/E09 使用同一视频，Video-MME-v2 的同组题也相关。开发、调参和最终留出评测应按视频或相关题组划分，不能把同一视频分散到不同阶段后仍当作独立泛化证据。

### 6.2 建议比较的方案

| 方案 | 内容 | 回答的研究问题 |
| --- | --- | --- |
| B0 直接基线 | 固定模型，按正式输入和现有采样直接回答 | 原始能力达到什么水平？ |
| B1 改进观察 | 向关键时刻分配观察，但仍直接作答 | 收益主要来自看得更准吗？ |
| B2 显式事实与假设 | 在 B1 上加入事实表、干预副本和候选核验 | 分离事实与假设有无收益？ |
| B3 按需执行 | 在 B2 上加入算术／规则／趋势算子或局部物理传播 | 哪些子型需要可执行中间步骤？ |

比较时固定模型与输入模态；尽量对齐视觉预算，并报告新增文本和调用成本。若存在更多观察、更大模型等混合变化，不能把全部收益归因于“R7 pipeline”。

较重的物理仿真、世界模型或独立核验模型可以是后续扩展，但应先证明当前错误来自动态推演能力，且额外成本值得。

### 6.3 有判别力的诊断与消融

| 实验 | 做法 | 要观察的结果 |
| --- | --- | --- |
| 时间范围审查 | 对所有返回帧、字幕、摘要和缓存记录检查来源范围 | 是否确实遵守 start/end，是否有未来内容混入 |
| 末尾状态作用 | 在相同允许范围和预算内比较均匀采样与末尾加密 | S1 的主要收益是否来自末尾动作阶段 |
| 状态结构作用 | 使用同一观察证据，比较散文摘要与显式事实／假设记录 | 是否减少身份混淆和实际／假设状态混写 |
| 确定性计算作用 | E05/E17/E19 类比较纯语言计算与有来源变量的算子 | 算术／排序正确性是否改善，事实错误是否仍占主导 |
| 多步链的作用 | 比较 E08/E09 等短链与直接复合答案 | 中间错误能否定位，链条是否增加不必要假设 |
| 干预敏感性 | 固定事实，构造不同 remove/set/delay 条件，人工标注或用可信环境产生新真值 | 输出是否响应条件变化；不可沿用原题答案 |
| 选项顺序作用 | 置换原始候选顺序并同步更新答案映射 | 是否只记字母、是否被首项或最长项吸引 |
| 语义边界审查 | 原生标签分组与人工视频审查后的执行子型分别报告 | 改善是否只发生在被误当预测的事实检索题 |
| 语言先验诊断 | 仅题干与选项、以及去掉关键视频证据的受控输入 | 视频证据提供了多少额外信息；不把此设置当正式得分 |

未来信息使用最好通过输入边界、来源日志和受控单元检查排查。只有在单独声明的研究诊断中，才考虑故意放开未来内容；这种结果不能进入合法预测准确率。

### 6.4 报告什么指标

**结果：** 每题正确性、原生标签准确率、机制子型准确率、每组样本数，以及按题／按子型的汇总。保留候选数 K，并额外报告单候选记录对结果的影响。小样本结论应标明区间或至少逐题结果。

**机制：** 在人工核验子集上检查定位、实体绑定、关键事实、干预实施、下游传播、规则／趋势模型、选项映射。若没有可信轨迹或干预真值，不能声称测得正式的物理预测误差。

**成本：** 读取的独特帧数、重复编码帧与裁剪数、视觉／文本 token、工具与模型调用次数、观察耗时、端到端耗时和预算耗尽比例。显式状态记录的文本成本也应计入。

**组分数：** Video-MME-v2 的官方评分包含组结构与非线性机制。抽出一个 R7 问题可以报告该子集单题准确率，但计算官方组分数需要完整组的实际预测和官方评分程序，不能填入其他题的标准答案。[官方评分说明](https://huggingface.co/datasets/MME-Benchmarks/Video-MME-v2)

建议沿以下顺序归因，避免把所有错误都称作“推理失败”：

~~~text
输入／观察协议
  → 锚点定位
  → 对象身份与关键事实
  → 题设干预理解
  → 动态／规则／趋势模型
  → 下游状态传播
  → 候选比较与答案映射
~~~
