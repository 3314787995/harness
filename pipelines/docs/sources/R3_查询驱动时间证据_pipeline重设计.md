# R3 查询驱动时间证据 Pipeline：重设计与实施规格

日期：2026-09-09<br>
适用模型：冻结的 **Qwen3-VL-8B-Instruct**。<br>
设计状态：方案设计，未运行原视频、未重跑模型、未新增准确率结果。

## 0. 结论与约束

下一版不应继续以“维护一个尽可能完整的全片事件账本”为中心，而应以“解决当前问题所需的少量视觉判定”为中心。保留媒体索引、原始输出、轻量候选和程序归约；取消常驻 B1/B2、每窗 O1/O2、全局两两关系判断、固定复核池，以及终局无依据默认 A。

统一的是执行器，不是每题相同的观察窗口。R3 内部根据事件单位使用四种观察配方：短动作周期、长活动/出现实例、锚点邻接与目标排序、时间/共现统计。这不是新增九类题目的外层路由器。

基础配置只有一个冻结 Qwen 模型，加媒体解码、抽帧、裁剪、时间戳映射、字符串匹配与确定性运算。无训练、无蒸馏、无额外 LLM，无必须依赖的 CLIP、RepNet、TransRAC、手部检测器。音频理解不在纯视觉基础配置中；仅保留合法字幕/ASR 的输入接口。

下文的帧率、窗口、输出长度、预算都是工程起点，不是论文结论、模型最优值或实测保证。

## 1. 根据材料定位旧方案的断点

依据《R3_特征与原题讨论材料.md》§5.3–5.4：

| 断点 | 已有材料支持的事实 | 重设计动作 |
|---|---|---|
| 输出进入状态失败 | v4 发射题 4 次基础观察和 4 次复核均未形成有效提交 | 原始响应立即保存；逐行接纳可解析候选；不以完整响应事务阻塞所有观察 |
| 事件单位错误 | v3 发射记录混入准备动作，纸动物记录混入制作子步骤 | 观察任务直接针对“一次发射”或“一个制作实例”，不先泛化描述再由文本造事件 |
| 关系判断错误 | 模型把实际重叠区间说成有明确间隔 | 数值时间关系由程序计算；视觉模型只处理不能由时间直接推出的连续性/身份 |
| 邻接链缺失 | 清洁题锚点不唯一、没有闭合 next；默认 A 恰好正确 | 保留多个锚点候选，只检查锚点到后继之间的连续片段 |
| 预算调度错误 | 尚有额度但被预留/可选步骤阻塞 | 必要观察队列与可选复核队列分开；可选失败不结束必要工作 |

这些事实并不证明 v4 的可修订时间线思想已经被充分检验，也不证明 Qwen 在给定采样下能够看懂发射。协议可用、事件语义正确、程序正确和答案正确必须分别记录。

## 2. 文献依据与借鉴边界

[P1] **Visual Programming: Compositional visual reasoning without training**，CVPR 2023。借鉴感知与程序执行分工；不让小模型自由生成任意 Python 或整个调用计划，使用有限运算模板。

[P2] **Counting Out Time: Class Agnostic Video Repetition Counting in the Wild / RepNet**，CVPR 2020。借鉴先识别周期与重复片段、再计算次数；它本身是训练方法，不能冒充本方案的免训练计数器。

[P3] **TransRAC: Encoding Multi-scale Temporal Correlation with Transformers for Repetitive Action Counting**，CVPR 2022。借鉴多时间尺度和逐周期意识，不以固定平均周期解释所有动作；不使用其训练好的网络作为隐含额外组件。

[P4] **VideoTree: Adaptive Tree-based Video Representation for LLM Reasoning on Long Videos**，CVPR 2025。借鉴与问题相关的粗到细观察；不照搬“相似帧只保留代表”去压缩计数视频，重复内容可能正是计数目标。

[P5] **VideoAgent: Long-form Video Understanding with Large Language Model as Agent**，ECCV 2024，Xiaohan Wang 等。借鉴围绕缺失信息补看；不用强 LLM 的开放式规划循环替代当前 8B 的局部感知。注意它与另一篇 Memory-augmented VideoAgent 不是同一论文。

[P6] **VideoINSTA: Zero-shot Long Video Understanding via Informative Spatial-Temporal Reasoning with LLMs**，Findings of EMNLP 2024。借鉴信息充分性意识；停止不直接依赖模型自报 confidence。

[P7] Qwen3-VL 官方模型卡与仓库。用于实际输入适配、视频时间元数据和像素约束，不将模型宣传中的长视频能力当作短动作计数保证。

上述文献支持的是组件思想，不证明下面组合能在你的 R3 上获得多少提升。

## 3. 总体流程

```text
合法题目与媒体
  → 冻结查询语义：事件单位、运算、范围、时间口径
  → 按运算生成必要观察任务
  → Qwen 一次带图输出少量局部候选
  → 程序保存原始输出、映射时间、建立轻量查询状态
  → 直接归约，并列出会改变答案的缺口
  → 对少量关键缺口进行一次有新视觉信息的补看
  → 程序重新归约与选项映射
  → 输出答案、证据基础、采样残余风险和成本
```

短视频能够在合适时间密度与视觉预算内装下时，直接进入局部观察，不先做粗摘要。短视频简单邻接可一次看完整允许片段直接回答并给出锚点/后继证据，无须先建立全片事件表。

长视频先建立有时间位置的候选索引，但该索引只负责“值得去哪里看”，不能自行证明没有遗漏，也不能用相似性聚类消除不同时刻的重复出现。

## 4. 查询规格：程序维护元数据，模型只解释语义

### 4.1 运算模板

用六个底层模板覆盖原有十二个接口，而不是六个模型代理：

| 底层模板 | 兼容旧运算 | 主要参数 |
|---|---|---|
| COUNT | count_occurrences | 目标、事件单位、合法范围、边界计入规则 |
| SELECT | first/last/first_k/last_k/nth | 前后方向、k、被读取属性、顺序口径 |
| ORDER | order_events | 目标列表、出现/开始/完成/现实时间口径 |
| NEIGHBOR | next_after_anchor / previous_before_anchor | 锚点、方向、是否最近、候选动作粒度 |
| MEASURE | localize_event / event_duration | 时间基准、所需边界、差值/区间/时长比较 |
| COOCCUR | cooccurrence_frequency | 主活动单位、共现条件、历史范围 |

已有上游明确运算时直接使用；自然语言有明确模板时由规则提取；只有需要语义消歧时额外调用 Qwen 一次。不要固定先调用 B1 和 B2。

### 4.2 示例

```json
{
  "op": "NEIGHBOR",
  "anchor_text": "cleaning her floor",
  "target_text": "the woman's subsequent activity",
  "direction": "after",
  "selection": "first",
  "unit": "activity"
}
```

合法范围来自 dataset adapter，程序附加，不由模型编造。模型不输出无关的 `k=null`，不输出事实 ID、预算、完成证明等字段。

新时间限制须来自原题或允许输入的明确规定。“Green Level 的前 15 秒”编译成相对阶段范围；“清洁之后 next”不能擅自加 15 秒截止。`after` 也不一律改成 `immediately after`。

`made` 未明确开始/完成口径时保留其原意。若开始与完成排序一致，可以避免额外消歧；若它们确实改变第二项，才需要检查任务定义与视频结构，不能固定按 offset 排序后宣称是真值。

### 4.3 选项与答案隔离

数字计数候选不进入事件检测；程序计出次数后再映射。身份/动作候选可去掉字母作为对称的识别词表，不能只提示当前偏好的候选。排序题应保留题目指定对象集合；像 Seal & Orca 这样的复合项可能帮助澄清计数单位。

答案键、人工证据区间和该讨论材料中的标准答案不进入任何运行时 prompt。MVBench 的允许输入 start/end 与动作真值 accurate_start/accurate_end 分开；前者由适配器按官方规则使用，后者仅供离线评分。预测截止以外的画面不得读取。

## 5. 媒体与 Qwen 输入适配

### 5.1 建立实际输入清单

每次推理保存 `video_id、合法范围、实际抽取帧列表、原视频 PTS、帧尺寸、裁剪框、processor 后的视觉 token 数、抽帧配置、模型/processor/工具版本`。

程序区分原视频时间、裁剪片段本地时间和模型所见时间标记。模型返回的是它确实见过的标记；程序查表映射到原视频，不相信模型自由生成的三位小数秒数。变帧率视频优先采用解码器提供的 PTS。

Qwen 官方示例提供 `image_patch_size=16` 与 `return_video_metadata=True` 的 Qwen3-VL 路径；使用 qwen-vl-utils 已完成缩放时，按官方路径传递 `do_resize=False`。帧率和二次采样的行为必须按实际后端核验，不能以客户端计划 fps 代替实际模型输入。[P7]

### 5.2 起始观察配方

| 场景 | 建议起点 | 关键注意事项 |
|---|---|---|
| 快速重复动作 | 核心 4–6 秒，8 fps，两侧各 1 秒上下文 | 约 48–64 帧；必要时缩短时间段后升至 16 fps 或原帧率 |
| 长活动/制作实例候选定位 | 24–32 秒，1 fps | 只定位实例转换与产品，不能据此宣布无短事件 |
| 锚点/候选边界回读 | 4–8 秒，8 fps | 包含锚点尾部和后继头部；长间隔继续前向扩展 |
| 成品类别、细字辨识 | 少量高分辨率帧或保留上下文的裁剪 | 只解决属性，不替代前缀顺序证据 |
| 长视频场景插入计数 | 全范围粗索引 + 候选与间隙审查 | 不能仅取相似度最高的 K 段后求和 |

这些设置不是全题固定超参。一次动作短于采样间隔时，模型可能根本看不到关键过程；升帧率要从原媒体重新解码，不是复制帧或只改时间标签。原视频本身缺失的信息无法用抽帧补回。

取证优先使用按时间组织的视频输入。接触表可用于粗定位，但不能默认与原生时序输入等价。局部裁剪必须包含相关对象和动作结果；把手裁清楚却把飞出的物体裁掉没有帮助。

### 5.3 输入与生成预算

视觉预算先尝试单调用约 6k–12k 视觉 tokens，由实际 processor 结果核算；这是工程上限起点，不是模型上下文上限。动作题优先保留时间分辨率，属性题优先保留空间分辨率。

普通观察建议 256–768 输出 tokens，局部复核 128–384；不因输出截断而删候选。出现截断时保存已完整解析的行，并将未解析部分记为缺口，必要时缩小窗口。

结构化抽取可先以固定种子、低随机性/贪心解码作可复现工程配置。Qwen 模型卡的通用 VL 推荐使用采样，不应把本方案的贪心设置说成官方最优设置。[P7]

## 6. 配方 A：短动作计数——标记一次发生，不写动作流水账

### 6.1 局部确定一次的视觉判据

题面定义目标语义；视频负责提供该目标在当前场景中的可见形态。第一次有效观察兼顾判断“什么构成一次”和提出候选，不单独创建一个永久的事件本体编译模块。

对发射，要求观察真正发射的可见证据，并区分准备、复位与结果；不要预先把某种按压机械流程写死。对画梯形，观察的是完整路径而非四个角点；对完整教学演示，只有题目/任务口径要求完整时才加入完整性条件。

若首个片段不够确认事件形态，标记单位/视觉不明确，不能为了完成流程制造一个正例。后续推翻早期理解时，先使受影响的候选失效，再只回看相关片段，不继续使用旧计数。

### 6.2 最小输出

每个候选一条独立 JSON 行，仅包含三项。以下完全是协议示例，不是真实发射题观测：

```jsonl
{"at":[12,15],"decision":"occurrence","note":"该区间可见目标动作实际发生"}
{"at":[26,30],"decision":"uncertain","note":"目标被遮挡，无法区分准备与发生"}
```

`at` 是输入中程序展示的时间/帧标记范围。`decision` 是模型判断，不是程序认证的真值。程序附加调用 ID、媒体来源、任务目标、稳定候选 ID；模型不同时维护 target_ids、relevance、target_id、fact_refs。

调用级另允许一个简短观察结果：目标可见、未见目标、动作无法辨清、输出不完整。纯空列表不得等价于“没有发生”。

### 6.3 核心区间归属

将范围划成互不重叠的核心区间 `C_j=[b_j,b_(j+1))`，最后一个区间允许包含合法末端。观察时加入上下文，但计数所有权只属于核心区间。

为每次目标发生选统一的见证位置，例如首次清楚发生的局部时刻。若其不确定范围完全落在一个核心区间，该事件归该区间；若跨缝，则暂不分配唯一归属，进行接缝回读。相邻窗口看到上下文里的同一次事件只提供支持，不再增加次数。

这只是工程去重规则，不是视觉事件识别器。不同窗口可能把同一次发生标在不同位置，同一核心内也可能重复报出；不能仅依时间接近或区间 IoU 自动合并。仅当跨窗候选确实竞争同一次发生时，读两者之间的连续原片段。

确认后的程序结果为 `count = 各核心区间拥有的独立事件数之和`。不维护所有事件对的 SAME/DISTINCT 图。

### 6.4 补看与条件上下界

只处理能改变次数的疑点：准备还是目标、一轮还是两轮、接缝归属、快速动作漏采、边界内还是边界外。不为每个已清楚动作精修起止到毫秒。

若必要范围已经按既定采样策略处理，且仅有明确列出的少量候选不确定，可以计算“在当前候选和已采纳视觉判断成立条件下”的次数区间。仍有未审查范围时，不得将已发现候选数当全片上界。零次同样需要合法范围和合格的阴性观察支持。

不建议基础版本用光流峰值、像素变化次数或固定周期直接给出最终次数。这些信号即便加入，也只能提示补看位置，不能替代目标语义判断。[P2][P3]

## 7. 配方 B：长活动/出现实例——先选实例，再读属性

纸动物题应按“第一个制作实例、第二个制作实例”组织观察，不按折纸、画眼睛、画鼻子、展示等微步骤建顶层事件。[材料 E02、§5.3]

### 7.1 实例候选的建立

首次粗扫寻找“新制作对象进入、旧成品退出、开始处理另一张材料、正式制作章节切换”等候选边界。切镜头、变更工具、出现一个动物名，都只是线索，不是新实例的充分条件。

跨窗口携带当前相关实例的一小段视觉尾巴与短描述，不只携带长文本账本。下一个窗口只需判断：继续同一实例、新实例开始、还是无法确定。出现新实例时才增加顶层候选，步骤只作为局部支持。

“猪脸再次展示”不自动形成又一个制作实例；同类动物被重新制作一次也不能按类别去重。如果并行制作导致身份或开始/完成顺序不一致，保留冲突而不是强行排序。

### 7.2 第 N 项选择

从允许输入起点前向处理到第 N 个可支持实例。闭合此前是否有未处理实例的缺口后，由程序执行 `selected = ordered_instances[N - 1]`，然后只读取该实例的清晰成品属性。

不能将“前两项”交给终局模型再次猜第二项。看到 Pig 文字只能支持某片段内容，必须绑定到已被选中的制作实例。

只要后续内容不会改变前缀中的实例/顺序，选第 2 个不需要精看第 3 个以后所有步骤。

### 7.3 出现序列的变体

类别首次出现：每个类别保留最早时间，但此前遗漏风险仍须审查。普通再次出现序列：相同类别隔开后再出现需要保留；连续同一出现跨窗则合并。`Tiger → Tiger` 不能因名称相同被删除。

`last_k` 从尾部向前选择观察区间，但每个区间内部仍按原方向播放；不要用倒放后的运动识别原动作。联合出现是否为一项按题目/候选定义处理。

现实比赛进球顺序与媒体镜头顺序分开。仅因两个画面相似不能证明回放；回放标志、比分、比赛计时与场面连续性可形成证据，仍不明确就保留 replay ambiguity。

## 8. 配方 C：锚点邻接与指定目标排序

### 8.1 清洁后继的执行方式

先定位清洁地板的候选区间。粗索引暂不唯一选锚点；可存在多处清洁。围绕每个仍可能相关的锚点末端读取连续片段，识别清洁结束和后续活动。

开始可读 4–8 秒，但这只是单次窗口，不是问题的时间范围。后续活动尚未出现时，向后扩展；不能因“超过 15 秒”而排除真正的下一项。

相同输入足够容纳锚点与后继时，一次 Qwen 调用同时输出两者及中间是否有其他候选动作，无需先建立所有家务活动的全片账本。

### 8.2 邻接粒度

“打扫之后的下一项家务”与“拉窗帘之后的第一个细小动作”应使用不同动作粒度。题面与候选可帮助定义该粒度。把“转头”自动吞进大活动，或把走路的每一步当作家务活动，都可能改变 next。

只有找到之后某动作，不足以说明它是最近后继。按既定采样策略检查两者之间的相关范围，并保留尚不能排除的小动作/切镜头间隙。

前驱则围绕锚点开始之前观察。重叠事件按任务对“之前/之后”的定义处理；不强制将所有活动压成一个无重叠全序。

### 8.3 多个锚点

多个锚点无需立即停止。若它们在合法语义下都导向相同选项，可记录“锚点仍不唯一但答案在这些已列出候选间一致”。这不是无遗漏保证；仍要检查是否遗漏另一种相关锚点。若不同候选导向不同答案，则只补看能区分这些锚点的片段。

### 8.4 指定事件排序

长视频排序四个指定事件时，只定位这四类事件及竞争位置，不枚举全部动作。两个事件的可靠时间范围不重叠时，程序直接判断先后；仅在范围重叠、重复出现或现实时间与镜头时间不一致时请求视觉消歧。

不要让 Qwen 再判断“4.0–7.7 与 4.1–4.9 是否重叠”这种数值关系。

## 9. 配方 D：定位、时长和共现频次

### 9.1 时间位置

“开头/中间/末尾/全程”先确认目标分布，再按 benchmark 合法定义映射；未明确官方阈值时，不把任意三等分说成官方标准。“全程”不能由一个中间正例推出。

### 9.2 时间基准先行

区分媒体时间、视频内计时器/日期、叙事现实时间。剪辑视频中停留镜头最长不一定代表实际停留最长。若答案由明确解说或文字直接给出，可使用合法局部事实，而不是强行做区间加法。[材料 E22、E23、B06]

开始边界 `s∈[s_L,s_U]`、结束边界 `e∈[e_L,e_U]` 时，在区间一致且事件实际结束不早于开始的条件下：

`duration ∈ [max(0, e_L - s_U), e_U - s_L]`。

边界区间冲突应先报错，不能套公式生成负时长。只精修足以影响选项的边界；不要凭候选是整数分钟反推视频边界。同地点多次停留先按正确身份求时间区间并集，避免窗口重叠双计。

### 9.3 共现频次

先建立独立主活动，例如一次喝咖啡，再判断该活动内是否有对应伴随活动。一个主活动对一个候选最多贡献一次，不按帧数或窗口数重复投票；共同在场也不自动等于共同弹奏。

候选 a 的按事件频次可定义为：`c(a)=sum_i 1[第 i 个独立主活动与 a 满足共现条件]`。频次率再除以合法主活动总数；分母不能是检索命中的方便子集。

多日历史要求合法查询截止、跨录像去重、主活动索引及参与者证据。基础纯视觉 runner 没有这些输入时不能声称已支持完整 EgoLifeQA。仅需提及的歌曲等语音证据，当前配置不可用时明确标记 modality unavailable，而非用生活常识回答。

## 10. 状态、校验与恢复

### 10.1 只存三层

原始层：请求、实际输入清单、原始响应、解析错误，收到后立即保存。

候选层：可解析局部观察、程序生成的 ID、时间映射、是否可参与当前查询。保存并不意味着确认。

结果层：程序所用候选、语义结果、选项映射、剩余缺口和证据基础。

一个候选引用越界，只隔离该候选；其他合法候选继续保留。未知引用不能自动替换为最近帧；事实目标归属错误不能通过文本修复伪造为正确。原始数据即使全错也保留供诊断，但不参与正证据或阴性证据。

### 10.2 修复规则

能确定性解决的空字段、外层代码围栏、类型规范化、精确候选匹配，由程序处理。完全相同媒体上反复重写复杂 JSON 不是默认路径。

不能从文本唯一确定的问题，只能变成视觉缺口。每个具体缺口至多一轮有新视觉信息的重读；新信息指更密帧、更清楚区域、更完整边界上下文，而不是同输入换措辞。仍未解决则输出部分或不确定，不再反复纯文本修复。

有条件支持结构化解码时可使用简单语法约束，但它只保证格式，不证明事件语义。协议不应要求模型维护循环关系和跨字段一致性网络。

### 10.3 更新方式

新观察推翻候选时，只替换受影响局部时间段/实例的候选版本，再重新运行依赖它的归约。无需让模型生成合并/撤销/拆分的通用事务语言；程序根据受控局部任务执行更新并记录前后版本。

## 11. 停止条件与补看调度

| 查询 | 必要观察范围 | 影响停止的关键问题 |
|---|---|---|
| 全片次数 | 全部合法范围 | 漏采、准备误计、接缝重复、范围边界 |
| first / nth / first_k | 足够前缀 | 更早实例、顺序口径、所选项属性 |
| last / last_k | 足够后缀 | 更晚实例、尾段是否处理完 |
| next / previous | 锚点与邻接范围；定位时可需全片索引 | 锚点竞争、两事件之间的更近候选 |
| 指定顺序 | 所有指定目标的相关位置 | 重复发生、时间范围重叠、回放 |
| 时长 | 被查询的边界与时间基准 | 边界不确定是否跨选项、时间语义错误 |
| 习惯频次 | 合法历史中的独立主活动 | 未观察主活动、共现身份、跨片重复 |

已抽帧不等于已覆盖语义，已覆盖语义不等于数学上无漏事件。保存最大采样间隔与未消除风险；答案只能是在当前视觉证据和采样假设下已确定。

执行器只使用两个队列：必要观察与关键缺口。先完成会改变答案的必要观察，再用剩余额度处理关键缺口。可选任务因预算不足被跳过，不应阻止仍有预算执行的必要任务。

缺口排序采用透明的规则：输入/语义错误优先；能够改变当前答案的候选优先；没有新媒体信息的同输入重复调用不入队。无需训练置信度、估计虚假的工具正确概率或引入复杂 Bayesian controller。

预算配置可写为：`总调用 = 0~1 次规格解析 + 必要观察数 + 有限关键补看数 + 0~1 次语义映射/最终视觉作答`。对短片可先设置额外补看总上限 2–3；不足以支持结论时如实停止，不把这个上限解释为任何长度视频都能数完。

## 12. 简化执行伪代码

下列是模块边界伪代码，不是已连接模型的可运行实现。

```python
def solve_r3(sample, adapter, reader, vlm, limits):
    # adapter 不将答案键、人工证据边界暴露给其他模块。
    permitted = adapter.allowed_input(sample)
    spec = make_query_spec(sample.question, permitted)
    state = QueryState(spec=spec)

    # 小片段无需额外粗扫；扫描计划由运算和单位确定。
    for job in make_required_jobs(spec, permitted, limits):
        if not limits.can_run(job):
            state.add_gap("required_observation_unfinished", job.interval)
            break
        media = reader.read(job, permitted)
        manifest = reader.actual_manifest(media)
        raw = vlm.observe(media, prompt_for(job, spec))
        state.save_raw(manifest, raw)   # 保存不依赖后续协议成功。
        state.ingest_rows_individually(parse_rows(raw), manifest)
        reduce_query(state)
        if query_can_stop_under_current_observations(state):
            break

    # 队列仅含能改变答案的缺口；每个缺口不反复同输入重试。
    for gap in prioritized_answer_changing_gaps(state):
        if limits.refinement_cap_reached():
            break
        job = new_visual_evidence_job(gap, state, permitted)
        if job is None or not limits.can_run(job):
            continue
        observe_save_ingest_and_replace_local_slice(job, state, reader, vlm)
        reduce_query(state)

    return map_answer_and_report_uncertainty(state, sample.options)
```

真实实现还需断言：任何读取不越过合法范围、时间来自实际清单、无效行不产生阴性证据、结果依赖版本更新后及时失效、所有成本都计入。

## 13. 可直接改写的提示词模板

### 13.1 短动作观察

```text
你看到一个按原顺序播放的视频片段。原题目标：{target}。
一次的单位：{unit_from_question}。
核心计数范围：{core}；两侧画面仅提供上下文。

只标记目标实际发生的候选，不逐条描述所有手部动作。
准备、复位、持续结果不独立算作目标；无法区分就标 uncertain。
每次独立发生至多一行，at 只能使用输入中展示的时间/帧标记。
不要输出总次数、全片答案或选项字母。
格式：{"at":[开始标记,结束标记],"decision":"occurrence|not_target|uncertain","note":"一句可见依据"}
如果没有候选，说明是未见目标、动作不可辨还是输入不完整。
```

### 13.2 制作实例观察

```text
原题需要按制作实例排序，不按制作步骤排序。
当前相关制作实例的视觉尾部：{optional_previous_visual_tail}。

判断本片段是继续同一制作实例，还是出现另一个新的制作实例。
折叠、绘制五官、展示同一成品，不各自新增实例。
仅有镜头切换或产品名称不足以证明新实例。
输出新实例的候选转换区间和可见理由；不确定请说明。
若可清楚识别成品，记录类别，但不要据类别猜序号。
```

### 13.3 邻接观察

```text
锚点：{anchor}。方向：{before_or_after}。
题目要求：{first_or_general_relation}。
候选动作词表：{all_unlabeled_candidate_texts_if_needed}。

观察锚点开始/结束附近的连续画面。
记录锚点边界候选、相关的前驱/后继活动，以及两者间的竞争活动。
不要仅凭“这个动作在后面”就说它是下一个。
若片段还未覆盖到后继、锚点有多个解释或动作不可辨，明确指出。
只使用所提供画面，不以生活常识补全顺序。
```

这些模板是任务约束，不是保证模型正确的证明。无需在每次调用中再次粘贴全部 R3 文档或其他题的答案。

## 14. 输出与失败的诚实表达

内部答案保持可空，不把缺证据变成 A。结果至少分开保存：

```json
{
  "semantic_answer": null,
  "choice": null,
  "answer_basis": "unresolved",
  "selected_evidence": [],
  "remaining_gaps": ["target_motion_not_resolved"],
  "sampling_assumptions": [],
  "cost": {"model_calls": 0, "visual_tokens": 0}
}
```

这里是字段示意，0 不是任何真实运行的成本。建议 answer_basis 使用 visual_direct、visual_reduction、partial_choice、forced_choice、protocol_failure 等清晰类别。

benchmark 强制选项时，可在预留的最终一次调用中给模型现有合法视觉证据直接作答，或使用事先规定的无证据回退；必须保留 forced_choice 标志。常规总体准确率仍包括所有样本与回退，不得通过剔除失败样本提高分数；“证据支持且正确”作为另一个指标报告。

程序能证明的是按其输入正确执行了 count/nth/interval 运算，不证明视觉候选全部为真、全片无漏检。

## 15. 实施顺序与验证

首先完成输入清单、实际采样检查、最小观察输出和逐行保存。随后实现三个已有回归任务所需的 COUNT、SELECT(nth)、NEIGHBOR。只有这三类的失败能稳定归因，再扩展前后 K、时长、历史共现。

不要一次实现十二种运算的完整事件图；不应重新引入“任何字段不齐全就不能回答”的所有权机制。

必要对照为：同一 Qwen 的直接视频 QA；只有更合理抽帧/裁剪的直接 QA；轻量候选 + 程序归约；最后加有限关键补看。按相同或成对约束的视觉 tokens、输入范围、帧分辨率和端到端成本比较，而非只对齐调用次数。

故障定位可做两个离线替换：给正确局部片段但不给答案，检查基础视觉判定；给人工正确的事件记录但不给答案，检查程序归约。它们只用于定位，不进入正式推理和成绩。

记录首次解析成功率、有效观察保留率、单位错误、漏检/重复、关系错误、选项映射错误、无证据回退率、总体准确率及成本。局部正确片段仍看不懂时，不能靠更长账本修复；真正瓶颈是感知输入/模型能力。正确事件输入仍选错时，优先修程序而不是追加视觉调用。

原三题和该材料中的机制例题已用于开发讨论，不能拿全通过证明泛化。泛化评估必须另用未参与设计的样本；本文件没有安排自动运行或新增测试。

## 16. 最重要的设计取舍

保留账本的可追溯性，放弃账本的中心地位。明确事件单位，但不要求小模型一次输出完整事件本体。保留局部补看，但不将补看设计成无上限的多代理推理。保留程序归约，但不把确定性算术包装成视觉真值。

新方案真正值得验证的主张是：在冻结的 8B 模型上，**按查询选择观察单位与时间分辨率，并只为会改变答案的缺口获取新视觉证据**，能否比单纯增加抽帧或调用更有效。这个主张需要结果支持，不能由模块命名或协议通过率代替。
